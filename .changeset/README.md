# Changesets

This directory uses [Changesets](https://github.com/changesets/changesets) to manage versioning across the monorepo.

## Adding a changeset

When you make a user-facing change, run:

```bash
npx changeset add
```

This will prompt you for:

1. Which packages are affected (multi-select)
2. The bump type (`patch`, `minor`, `major`)
3. A short summary of the change

The result is a new markdown file in `.changeset/` that the version-bot uses to update `package.json` versions and generate `CHANGELOG.md` entries.

## Releasing

```bash
npx changeset version   # bump package versions, update CHANGELOG.md
npx changeset publish   # publish to npm
```

The CI workflow runs `changeset status` on every PR and uses the GitHub bot
to publish new versions when a PR is merged into `main`.

## Why changesets (and not a single CHANGELOG.md)?

A single hand-maintained `CHANGELOG.md` is fine for a single package, but the
monorepo has six independently-versioned packages. Changesets gives us
per-package versioning with autogenerated changelogs that match what was
actually published.
